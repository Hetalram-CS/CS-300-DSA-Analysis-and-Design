# CS-300-DSA-Analysis-and-Design
CS 300 DSA: Analysis and Design coursework and portfolio projects

This repository contains my work from CS 300: DSA Analysis and Design. The projects demonstrate my understanding of data structures, algorithms, runtime analysis, and C++ programming.

What was the problem you were solving in the projects for this course?

The main problem I was solving was creating an advising assistance program for the Computer Science department at ABCU. The program needed to read course information from a file, store the course data, print all courses in alphanumeric order, and allow a user to search for a course and view its prerequisites.

How did you approach the problem? Why are data structures important to understand?

I first compared three different data structures: a vector, hash table, and binary search tree. I created pseudocode and analyzed the runtime and memory requirements of each structure. Understanding data structures is important because the structure we choose affects how efficiently a program can store, search, and organize information. I selected a binary search tree because an in-order traversal naturally prints the courses in alphanumeric order while also supporting course searches.

How did you overcome any roadblocks you encountered?

I worked through the project step by step. When I encountered problems, I reviewed my pseudocode, checked the program logic, corrected errors, and tested each function separately. I tested loading the course file, printing the complete course list, searching for an individual course, displaying prerequisites, handling invalid input, and exiting the program. Testing each part helped me find problems and confirm that the complete program worked correctly.

How has your work on this project expanded your approach to designing software and developing programs?

This project taught me that planning before coding is very important. Instead of immediately writing C++ code, I first considered different data structures, created pseudocode, and analyzed their efficiency. I learned to think about runtime, memory usage, searching, sorting, and the requirements of the program before choosing a solution.

How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?

I learned to organize my programs into smaller functions and use meaningful names, comments, and clear program logic. In Project Two, I separated tasks such as loading course data, searching the binary search tree, printing courses, and displaying prerequisite information. This makes the code easier to read, test, maintain, and modify in the future.
